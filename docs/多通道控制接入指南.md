# 多通道控制接入指南（蓝牙 HC-05 / WiFi ESP-01S）

> 适用固件版本：STM32F407 + 三路 USART 控制源（USART1 PC / USART2 蓝牙 / USART3 WiFi）
> 更新日期：2026-09-14

## 1. 系统架构

```
┌──────────────┐   USART1(PA9/PA10)   ┌──────────────────┐
│ PC 上位机     │ ───────────────────► │                  │
│ arm_host.py  │ ◄─────────────────── │                  │
└──────────────┘                      │   STM32F407      │   I2C    ┌─────────┐
┌──────────────┐   USART2(PD5/PD6)    │   协议栈 v1       │ ───────► │ PCA9685 │──► 六路舵机
│ HC-05 蓝牙    │ ───────────────────► │  （三串口统一解析，│          └─────────┘
│ （手机）      │ ◄─────────────────── │   应答回发来源串口）│
└──────────────┘                      │                  │
┌──────────────┐   USART3(PB10/PB11)  │                  │
│ ESP-01S WiFi │ ───────────────────► │                  │
│ （手机 TCP）  │ ◄─────────────────── │                  │
└──────────────┘                      └──────────────────┘
```

- 三个串口共用同一套协议引擎：`$<CMD>[,<ARG>...]*<CK><CR><LF>`，CK 为 XOR 校验。
- 应答**回发命令来源串口**：谁发的命令，谁收到应答。
- 所有命令在任意通道上完全等价：`PING/STATE/HOME/STOP/RESUME/MANUAL/MOVE/JOINT/REC/RECEND/PLAY/TNUM/CLEAR/LOG`。

## 2. 硬件接线

### 2.1 HC-05 → STM32（USART2）

| HC-05 | STM32F407 | 说明 |
|---|---|---|
| VCC | 5V（独立供电更稳） | 蓝牙连接瞬间电流大，避免从引脚取电 |
| GND | GND | 必须共地 |
| TXD | PD6（USART2_RX） | 模块发送 → 单片机接收 |
| RXD | PD5（USART2_TX） | 建议串 1kΩ 电阻保护 |

### 2.2 ESP-01S → STM32（USART3）

| ESP-01S | STM32F407 | 说明 |
|---|---|---|
| VCC | 3.3V（独立稳压） | **禁止接 5V** |
| GND | GND | 必须共地 |
| RX | PB10（USART3_TX） | 建议串 1kΩ 电阻 |
| TX | PB11（USART3_RX） | |
| EN(CH_PD) | 3.3V | 拉高使能 |

## 3. HC-05 配置

1. 用 USB-TTL 单独接 HC-05（**不要连 STM32**），EN/KEY 拉高进入 AT 模式；
2. 按模块当前波特率（出厂常见 9600）发送：

```
AT                    → OK
AT+NAME=ARM-BT        → OK    蓝牙名
AT+UART=115200,0,0    → OK    波特率 115200 8N1（与固件一致，关键！）
AT+PSWD=1234          → OK    配对密码
```

3. 断开电源，EN 拉低后重新上电进入透传模式，再接 STM32。

手机验证：蓝牙串口 APP（如 Serial Bluetooth Terminal）配对 `ARM-BT`/`1234`，发送 `$PING*10`，应回 `$OK,PONG*XX`。

## 4. ESP-01S 配置

### 4.1 手动配置（首次 / 排障用）

USB-TTL 单独接 ESP-01S，115200 8N1：

```
AT                       → OK
AT+CWMODE=2              → 设 AP 模式（自建热点）
AT+CWSAP="YOUR_SSID","YOUR_PASSWORD",5,3   → 热点名/密码/信道/加密(WPA_WPA2_PSK)
AT+RST                   → 重启生效（等 3 秒）
AT+CIPMUX=1              → 多连接（开 TCP server 需要）
AT+CIPSERVER=1,9000      → 开 TCP server，端口 9000
```

> 注意：`CIPMUX=1 + CIPSERVER` 时 **CIPMODE 透传不可用**（老固件报 `CIPMUX and CIPSERVER must be 0`）。本系统**不需要透传**：手机→STM32 方向数据带 `+IPD,0,n:` 前缀，STM32 协议栈自动剥除；STM32→手机 方向应答由 ESP 自动转发到当前 TCP 连接。

### 4.2 断电自动恢复（STM32 自动配置）

固件 `wifi.c` 的 `WIFI_Init()` 在 STM32 上电后自动执行（无需人工 AT）：

1. 等待 2 秒（等 ESP 就绪）；
2. `AT` 唤醒 → `AT+CWMODE=2` → `AT+CWSAP="YOUR_SSID","YOUR_PASSWORD",5,3`；
3. `AT+RST` 重启 ESP，等其输出 `ready`（超时 6 秒）；
4. `AT+CIPMUX=1` → `AT+CIPSERVER=1,9000`；
5. 注册协议栈，开始接收命令。

**特性**：CWMODE/CWSAP 存 ESP flash（断电保留），CIPMUX/CIPSERVER 不存 flash（断电丢失）——所以每次上电由 STM32 重新下发，**ESP 断电重启无需人工重配**。开机约 10 秒后热点（`WIFI_AP_SSID`）可用。

## 5. 手机 WiFi TCP 测试

1. 手机 WiFi 连接 `YOUR_SSID`，密码 `YOUR_PASSWORD`；
2. TCP 调试助手（安卓"有人网络助手"/"网络调试助手"）新建 **TCP Client**：
   - 服务器 IP：`192.168.4.1`
   - 端口：`9000`
   - 工作模式选 **TCP 客户端**（不要选 Modbus_TCP）；
3. 连接成功后发送 `$PING*10`（**打开"追加 CRLF/发送新行"**，STM32 协议栈以 `\r\n` 结尾解析）；
4. 收到 `$OK,PONG*XX` = WiFi 通路打通。

## 6. 演示脚本

```powershell
cd tools

# 主通道 = PC 串口（步骤 8 自动另开 WiFi TCP 演示）
python demo.py --port COM7

# 主通道 = WiFi TCP（手机连自建热点后也可用手机 TCP 工具同步操作）
python demo.py --wifi 192.168.4.1:9000
```

演示流程：PING → 回 HOME → J1 摆动 → J6 夹爪开合 → J5 腕旋转 → 回 HOME → 手机蓝牙演示 → WiFi TCP 演示 → 回 HOME。

## 7. 网页遥控

```powershell
python web_control.py --serial COM7                # 经 PC 串口控制
python web_control.py --wifi 192.168.4.1:9000      # 经 WiFi TCP 控制（需手机/电脑连自建热点）
```

手机浏览器打开 PC 的 `http://<本机IP>:5000`，滑杆拖动实时控制、1 秒轮询回填实际脉宽。

## 8. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 蓝牙连上即断 | 供电不足（常见） | 独立供电 + 共地；换带底板原版模块 |
| 手机能连热点但 TCP 连不上 | CIPSERVER 没起来（断电丢失） | STM32 重新上电自动配置；或手动重发 AT+CIPMUX/CIPSERVER |
| `AT+CIPMODE=1` 报 ERROR | CIPMUX+CIPSERVER 与透传互斥 | 不需要透传，跳过该命令 |
| TCP 发 `$PING*10` 无应答 | 没开"追加 CRLF" | 打开"发送新行/CRLF"选项 |
| ESP 每命令回 `busy p...` | 模块处理慢 | 每条命令等回 OK/ready 再发下一条；固件即按此方式逐条等待（超时 3~6 秒），不用固定延时 |
| 三个通道同时发命令 | 状态机冲突 | 协议栈按命令顺序执行，仲裁按先到先服务 |
