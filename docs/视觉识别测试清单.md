# 机械臂视觉 · 识别与坐标标定测试清单

> 目标：验证视觉模块（颜色/形状识别、HSV 阈值、像素→毫米坐标标定、联调）全部符合预期。

## 0. 准备（5 分钟）

| 项 | 值 |
|---|---|
| Python | 3.10+（本机用 `python`，**不要用 `py`**） |
| OpenCV | `python -c "import cv2; print(cv2.__version__)"` 能打印版本号 |
| 摄像头 | USB 摄像头，Windows 自动识别 |
| 测试图 | `vision/sample.png`（由 `make_sample.py` 生成）、`vision/chessboard.png` |
| 标定板 | **A4 纸一张**（210×297mm，当标定板用，无需打印棋盘格） |
| 测试物 | 红/绿/蓝/黄 积木块或纸片（圆/方/三角/矩形更好） |
| 工作目录 | 所有命令先 `cd vision` |

⚠️ 常见坑：`py` 可能是另一个 Python（3.14）没装 cv2；摄像头被占用（微信/相机开着）会打不开；光照太暗/太亮会导致识别不到。

## 4. HSV 阈值调校（真实光照必做）

> 默认阈值是按通用值+合成图调的，**真实光照下必须重新标定**。这是识别准不准的关键。

| # | 操作 | 预期结果 | 通过 |
|---|------|----------|:---:|
| 4.1 | `python hsv_tuner.py --source 0` | 弹出窗口：左=原图，右=黑白掩膜 | ☐ |
| 4.2 | 按 `r`/`g`/`b`/`y` | 分别载入红/绿/蓝/黄的初始阈值 | ☐ |
| 4.3 | 拖 6 个滑条（H/S/V 上下限） | 目标物在右图变成**实心白色**、背景尽量黑 | ☐ |
| 4.4 | 按 `p` | 终端打印当前阈值片段（形如 `"red": {"ranges": [...]}`） | ☐ |
| 4.5 | 把打印的片段回填 `config.json` 对应颜色，保存 | 文件保存成功 | ☐ |
| 4.6 | 重跑 `python demo.py --source 0` | 识别明显变准，误识别减少 | ☐ |

> 红色特殊：色相跨 0/180 两端，`config.json` 里 red 有两段 `[0,10]+[170,180]`，调色时两段都要看。

## 5. 单应性标定（像素→毫米，四点法 + A4 纸）

> 不需要打印棋盘格。A4 纸尺寸固定 210×297mm，当标定板用。

| # | 操作 | 预期结果 | 通过 |
|---|------|----------|:---:|
| 5.1 | A4 纸平铺在工作台，摄像头固定俯视，纸完整入画 | 画面里能看清 A4 纸四角 | ☐ |
| 5.2 | `python homography.py --source 0 --mode points --width 297 --height 210 --out homography.json` | 弹出窗口，提示"click 4 corners" | ☐ |
| 5.3 | 按顺序点 A4 纸四角：左上→右上→右下→左下 | 4 个红点按 1/2/3/4 标出 | ☐ |
| 5.4 | 按 `d` | 打印"已保存单应矩阵 -> ...homography.json" | ☐ |
| 5.5 | 确认文件 | `homography.json` 存在于 vision 目录 | ☐ |

> 顺序点错会导致坐标错乱；`--width/height` 必须与标定物一致（此处为 A4 纸 297/210），否则毫米数全错。
> 注：本节为早期"用 A4 纸当标定板"的验证法；现行抓取流程（见《完整功能演示流程》）改为按**工作区实际尺寸**标定（如 250×200），并配合 `set_roi.py` 生成 ROI，两者口径不同，勿混用。

## 6. 联调验证（识别 + 坐标换算，核心验收）

> 把积木块放在 A4 纸上已知位置，看换算出的毫米坐标对不对。**误差 ≤5mm 算通过。**

| # | 操作 | 预期结果 | 通过 |
|---|------|----------|:---:|
| 6.1 | `python locate.py --source 0 --homography homography.json` | 弹出窗口，目标上有框+标签+`mm(x,y)` | ☐ |
| 6.2 | 积木块放 A4 纸**正中心**（≈148,105mm） | 打印 `mm(148.x,105.x)`，误差 ≤5mm | ☐ |
| 6.3 | 积木块放 A4 纸**左上角附近**（≈30,30mm） | 打印 `mm(30.x,30.x)`，误差 ≤5mm | ☐ |
| 6.4 | 积木块放 A4 纸**右下角附近**（≈270,180mm） | 打印 `mm(270.x,180.x)`，误差 ≤5mm | ☐ |
| 6.5 | 换不同颜色/形状的积木块各测一次 | 坐标仍准确，颜色/形状标签正确 | ☐ |

> 若 6.2~6.4 误差大：检查 5.3 四点是否点准、`--width/height` 是否填对、摄像头是否太斜（尽量正俯视）。

## 7. 边界情况（重点，答辩加分）

| # | 操作 | 预期结果 | 通过 |
|---|------|----------|:---:|
| 7.1 | 同时放 3~4 个不同颜色/形状目标 | 全部识别，互不干扰，各自坐标正确 | ☐ |
| 7.2 | 目标被手指/纸片挡住一半 | 仍能识别（或稳定不误判），不崩溃 | ☐ |
| 7.3 | 改变光照：开灯/关灯/侧光 | 识别结果稳定（必要时重调阈值） | ☐ |
| 7.4 | 工作台外放一个红色物体（背景干扰） | 会被识别（全图识别），但坐标是外推、不准——**属正常** | ☐ |
| 7.5 | 目标移出画面再移回 | 移出时无目标，移回后重新识别，不卡死 | ☐ |
| 7.6 | （可选）配 ROI：`config.json` 设 `"roi":[x,y,w,h]` | 只识别矩形内目标，背景误识别消失 | ☐ |

> 设计说明（面试点）：7.3 说明为什么用 HSV 而非 RGB（色相 H 对亮度更鲁棒）；7.4 说明"识别范围≠坐标准确范围"，单应矩阵只在标定区域内准确；7.6 的 ROI 是可选优化，坐标已自动加回全图偏移。

## 附：常用命令速查

```powershell
cd vision

# 合成图验证（无硬件）
python make_sample.py
python demo.py --source sample.png

# 摄像头实时识别
python demo.py --source 0

# 调 HSV 阈值（真实光照必做）
python hsv_tuner.py --source 0

# 像素→毫米标定（四点法 + A4 纸）
python homography.py --source 0 --mode points --width 297 --height 210 --out homography.json

# 联调验证（识别 + 坐标换算）
python locate.py --source 0 --homography homography.json

# 相机内参标定（可选加分项，需棋盘格）
python calibrate_camera.py --source 0 --grid 9x6 --square 25 --out camera.json
```

**测试顺序建议**：1 → 2 → 3 → 4 → 5 → 6 → 7。其中 4（调阈值）和 5（标定）是让 6 通过的前提，务必按序做。
