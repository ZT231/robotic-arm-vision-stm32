一、项目简介
--------------------------------------------------------------------
本项目以 STM32F407VET6 为主控，搭建六自由度机械臂视觉抓取平台，
打通"视觉识别 -> 坐标解算 -> 逆运动学 -> 机械臂抓取"完整链路。
系统支持串口（PC 上位机）、蓝牙（HC-05）、WiFi（ESP-01S）、
RFID（RC522 刷卡）四种控制通道，全部复用同一套指令协议
（$CMD*校验码\r\n，XOR 校验），可分别独立演示。

主要功能：
  1. 视觉引导抓取：USB 摄像头识别目标（HSV 颜色阈值 + 轮廓检测），
     Homography 四点标定完成像素->毫米换算，逆运动学解算 6 路脉宽，
     按目标形状自适应夹爪方向（沿边抓取），远目标自动前倾扩臂；
  2. 多通道控制：串口/蓝牙/WiFi/RFID 四通道共用统一协议；
  3. 模式状态机：CMD（待命）/ MANUAL（电位器手控）/ ESTOP（急停），
     RFID 双卡刷卡在 CMD 与 MANUAL 之间切换；
  4. 示教回放：上位机 REC 采集轨迹，PLAY 一键回放。

三、运行方法（简述）
--------------------------------------------------------------------
  固件：Keil 打开 MDK-ARM/Robotic arm vision.uvprojx 编译下载。
        接线与引脚分配见《docs/多通道控制接入指南.md》。

  上位机：python tools/arm_host.py --port COMx
         （蓝牙：--port COMx 接 HC-05；WiFi：--wifi 192.168.4.1:9000）

  视觉抓取（先在 vision 目录下标定）：
    python homography.py --source 0 --mode points --width X --height Y --out homography.json
    python set_roi.py --homography homography.json --width 250 --height 200
    python grasp.py --source 0 --homography homography.json --port COMx \
           --grip-conv 90 --off-x 1.5 --off-y 1.0

  详细操作与演示步骤见《docs/完整功能演示流程.md》。

四、开发中遇到的问题及解决方法
--------------------------------------------------------------------
以下按模块记录开发过程中实际遇到、并已解决的问题，附根因分析。

【4.1 RFID 刷卡（RC522）】
  问题 1：RC522 初始化时好时坏，版本寄存器读回 0x00/0xFF。
    原因：SPI 模式（硬件 SPI Mode 3）与模块时序不匹配；RST 引脚
          空闲电平实测仅 2.2V，低于模块复位阈值 2.31V，芯片处于
          未复位/复位中状态；后期旧模块本体射频前端损坏（换新
          模块后全程 Ver=0x82 稳定）。
    解决：恢复 CubeMX 默认 SPI Mode 0，波特率降为 2.625MHz；
          版本校验改为非阻断（仅诊断打印）；增加芯片失联兜底：
          Ver=00/FF 时执行硬件 RST 脉冲（20ms 低 + 20ms 高）+
          软复位 + 重配寄存器，读卡能力自动恢复。

  问题 2：刷卡无反应，调试输出 "REQA fail Irq=00 Err=00"。
    原因：定时器应答窗口小于接收等待循环时长，时序颠倒——
          窗口 = (TPrescaler+1)*(TReload+1)/13.56MHz；原 TReload
          偏大使窗口达 12.5ms，而循环 1000 次 x 硬件 SPI 每读
          ~8us 仅 ~8ms，循环先耗尽，定时器中断(TimerI)永远来
          不及置位，芯片误判"无卡"。
    解决：窗口缩至 3.2ms（TReload=0x00FA），循环加长到 3000 次
          （约 20ms）。判据：无卡时应见 Irq=01，若 Irq=00 说明
          窗口与循环时序颠倒，需再次调整。

  问题 3：刷卡偶发失败（Irq=64 / Err=40）。
    原因：供电瞬态或接触不良导致芯片偶发复位；Err=40 为射频错误。
    解决：检测周期仅在 1~2ms 内开启天线、随后立即关闭以降低
          平均电流；保留硬件 RST + 软复位恢复机制（静默执行，
          不打印）；最终确认旧模块硬件损坏，换新模块根治。

【4.2 蓝牙（HC-05）】
  问题 4：手机连接后频繁掉线，指令无响应。
    原因：模块直接由 STM32 的 3.3V 引脚供电，蓝牙建链瞬间电流
          不足导致射频复位；另有一批克隆模块设备名非标准
          （如 '111ZT'）固件不兼容导致 SPP 连接失败。
    解决：改用独立 3.3V/5V 稳压电源供电并共地；AT 模式配置
          波特率 115200、8N1、名称 ARM-BT、密码 1234；
          必须 EN/KEY 拉低断电重启进入透传模式后才可收发指令。

【4.3 WiFi（ESP-01S）】
  问题 5：TCP 服务器模式下客户端收不到 UART->TCP 数据。
    原因：CIPSERVER（CIPMUX=1）与透传模式（CIPMODE=1）在克隆
          固件上不能共存；且非透传模式下 UART->TCP 转发不会自动
          发生，需用 AT+CIPSEND=0,长度 包封。
    解决：固定使用 CIPMODE=0 + AT+CIPSEND 包封转发；命令之间
          必须等待 'OK'/'ready' 应答（AT+RST 要等 'ready' 而非
          首个 'OK'），不能用固定延时，否则命令丢失（busy p...）。

  问题 6：CIPMUX/CIPSERVER 掉电丢失。
    解决：上电后由 STM32 主循环重新配置，不依赖模块 flash 保存。

【4.4 机械臂标定与逆运动学】
  问题 7：J3/J4 大角度前倾区线性度差，角度拟合误差达 106°。
    原因：舵机在大角度区输出非线性，且 J3 角度测量方向取反。
    解决：改为 5 点分段标定，校正角度方向符号后重测。

  问题 8：夹爪方向整体偏 90°，沿边抓取失败。
    原因：J5 标定时误以夹爪轴线为基准，实际应以夹爪两指连线
          方向为基准。
    解决：按两指连线方向重新标定 J5，并用 --grip-conv 90 约定
          J5=0 时张开方向相对臂前向的关系。

  问题 9：夹取点相对 J5 旋转轴横向偏心约 1cm，出现位置相关偏差。
    原因：逆解按夹爪中心计算，未考虑偏心导致的方向角偏差（±3°）。
    解决：基于 J5 轴点方位（而非目标点方位）建立偏心补偿模型；
          直立抓不到时前倾角每次 +5°（上限 45°）逐步扩臂。

  问题 10：J1/J2 端点脉宽可能堵转，长时间大角度过热。
    解决：端点只做快速测量，不长时间停留；各关节软限位/中位
          全部按实测标定值写入 main.h（J3/J4 限位 520~2500us，
          J5 为 500~2500us，各关节有独立 SERVO_Jx_MID 中位宏）。

【4.5 视觉识别与抓取】
  问题 11：相机画面目标乱跳、抓取目标重复。
    原因：反光重影、按面积排序抖动、杂物误识别。
    解决：工作区 ROI 裁剪 + min_area 面积过滤 + 大工作区下把
          min_area 从 500 调至 200~300 + 帧间处理，画面干净稳定。

  问题 12：工作区边缘目标方向角偏、抓不准。
    原因：相机挂高不足覆盖大工作区（250x200mm），目标越靠边缘、
          相机越斜，像素形状畸变越大。
    解决：相机挂高覆盖全视野，光轴与桌面垂直偏差控制在 10~15°
          以内；ROI 像素框用 set_roi.py 按工作区实测自动计算，
          四点围成矩形内精度最佳。

  问题 13：标定后抓取位置偏移。
    原因：标定后挪动了相机或机械臂底座，homography 与
          base_x/base_y 只对同一固定安装有效。
    解决：相机固定安装（眼在外）后不要挪动；标定后把①原点的
          机械臂坐标实测填入 config.json 的 base_x/base_y，
          换过位置或相机就重新执行四点标定。

【4.6 串口协议与固件】
  问题 14：多串口同时收发时偶发数据错乱。
    原因：uart_protocol 发送为双缓冲（活动槽 + 备用槽），tx_busy
          期间 ISR 写备用槽，主循环搬运与发送前置位存在竞态。
    解决：搬运与发送前置位两处用 __disable_irq/__enable_irq 保护，
          避免 ISR 误写活动槽或破坏拷贝。

  问题 15：蓝牙指令返回 $ERR,2。
    原因：校验码错误。
    解决：上位机自动计算 XOR 校验码（$MOVE,0,1800*25 等），
          无需手算。

  问题 16：编译报 huart2 未定义 / 链接缺少 bt、wifi 模块。
    解决：stm32f4xx_it.c 的 USER CODE Includes 段 #include "usart.h"；
          bt.c、wifi.c 手动加入 Keil 工程的
          Application/User/Core 分组。

五、验收演示要点（15 分钟建议流程）
--------------------------------------------------------------------
  1. 系统架构讲解（2 min）：三层架构 + 统一指令协议 + 多串口路由；
  2. PC 上位机控制（3 min）：PING/STATE/HOME、单轴微调、
     示教 REC->PLAY 回放；
  3. RFID 刷卡切换（3 min）：钥匙扣刷入 MANUAL 电位器手控，
     卡片刷回 HOME/CMD；
  4. 视觉自动抓取（4 min）：放目标 -> 识别 -> 分步抓取 -> 码放，
     展示沿边夹取与远目标前倾；
  5. 无线通道（3 min）：蓝牙手机 APP / WiFi TCP 客户端发指令控制。

演示前务必确认：相机固定（眼在外）下标定完成；config.json 的
base_x/base_y、ROI 与实际一致；电位器在 MANUAL 模式下可用。
