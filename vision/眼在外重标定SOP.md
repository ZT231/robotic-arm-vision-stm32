# 眼在外（固定摄像头）重新摆放后 → 完美抓取 完整步骤（详细版）

适用时机：**机械臂底座移动 / 摄像头移动或角度变 / 标定点①位置改变** 之后。
按顺序执行，每步有【操作】【预期】【完成标准】【失败排查】，全部通过后即可直接正常抓取。

---

## 0. 准备工作（只做一次）

### 0.1 进入工作目录

所有命令都在 `vision` 目录下运行（所有 json 文件也在这里）：

```
cd vision
```

### 0.2 认识 3 个关键文件（它们互相绑定）

| 文件 | 作用 | 什么时候变 |
|---|---|---|
| `homography.json` | 像素↔毫米映射矩阵 H（视觉坐标系） | 摄像头/标定点变了就重标 |
| `config.json` | `base_x/base_y`（J1 在视觉坐标系的位置）、`roi`、`min_area`、颜色阈值 | H 变了必须跟着重标 base、重算 roi |
| `arm_params.json` | 机械臂结构参数（连杆长度、舵机限位） | 基本不动 |

**铁律：H、base、ROI 三者绑定。H 一变，base 和 ROI 必须重做。** 否则视觉坐标对、机械臂抓取错。

### 0.3 前置检查

- 机械臂、摄像头已固定，不会滑动；
- 摄像头能被打开（没有被其他程序占用，如微信/相机）；
- 准备：直角尺（对齐标定点用）、4 个可反复放置的标记物（硬币/胶带/小方块）、1 个待抓目标物。

---

## 1. 物理摆放（硬件）

### 1.1 摄像头

1. 固定在支架上，**镜头大致垂直台面**：光学轴与台面垂线的夹角控制在 **±10~15° 内**。
   - 太斜的后果：远处分辨率低、方块变成梯形（形状判断错）、方向误差随距离变大。
2. 高度以画面**完整覆盖整个工作区**为准，工作区尽量落在画面中部（边缘畸变大）。

### 1.2 标定点布局（推荐，工作区 250×200mm，X=臂右 250、Y=臂前 200）

在台面放 4 个标记物：

- ① = J1 投影点**左侧 10cm、正前方 10cm**（即 J1 左前 10cm）
- ② = ①沿**机械臂正右**方向 250mm
- ③ = ②沿**机械臂正前**方向 200mm（与①成对角）
- ④ = ①沿**机械臂正前**方向 200mm

结果：工作区 X[-10,+15]cm、Y[10,30]cm，J1 投影点落在工作区内，中心距 J1 约 22cm（垂直抓取基本可达，更远的自动前倾）。

> 若摄像头画面覆盖不到 J1：把①整体往**远离 J1** 方向平移（②④仍沿臂右/臂前），保证 4 点在画面内。① 放哪都行，base 由第 4 步实测，但工作区太远会导致远处目标前倾到 45° 也够不到——尽量让工作区靠近 J1。

**【最关键的一步】② 必须沿机械臂正右、④ 必须沿机械臂正前（用直角尺对准）。**
这是视觉坐标系与机械臂坐标系重合的唯一保证。对不齐 → 后面方向必偏、越远越偏。

✅ 完成标准：4 个标记物肉眼清晰可见、全在画面内、②④方向用直角尺对齐。

---

## 2. 标定 homography（摄像头或标定点动过 → 必做）

### 操作

```
python homography.py --source 0 --mode points --width 250 --height 200 --out homography.json
```

弹窗出现后（注意：是**静态帧**，先摆好 4 个标记物再运行）：

1. **鼠标左键依次点 4 个标记物中心**，顺序必须是：
   - 点 1 = ①（画面标注 `1.原点(0,0)`）
   - 点 2 = ②（画面标注 `2.X轴(W,0)`）
   - 点 3 = ③（画面标注 `3.对角(W,H)`）
   - 点 4 = ④（画面标注 `4.Y轴(0,H)`）
2. 点满 4 个点后按 **`d`** 求解保存。
3. 按 **`q`** 退出窗口。

### 预期输出

```
重投影误差: 平均 1.2 px / 最大 2.8 px
已保存单应矩阵 -> D:\...\vision\homography.json
```

### 完成标准 / 失败排查

- ✅ 终端出现"已保存单应矩阵"；
- 出现 `重投影误差` 提示：误差反映点击精度（世界四角反投影回像素与点击点的偏差），
  **平均 <2px、最大 <5px 属正常**；出现"标定精度低（最大误差 >5px）" → 点击位置不准，重跑标定；
- 出现"4 点近似共线或重合，标定无效" → 4 个点挤在一条线上/重合了，重新依次点击 4 个角；
- 点错任何一点 → **直接重跑整条命令**，不要补点；
- `--width/--height` 必须与你实际工作区尺寸一致（现在是 250×200）；
- 弹窗里看不到某标记物 → 摄像头没覆盖全，回去调 1.1/1.2。

---

## 3. 确认 grasp.py 用对文件（必做，防止旧文件坑）

**踩过的坑：`homography.json` 是旧标定、新标定存到了别的名字，导致 mm 坐标全乱。**

检查 `homography.json` 的修改时间是不是**刚刚**（当前时间）：

```
Get-Item homography.json | Select-Object LastWriteTime
```

- 如果时间不是刚才标定的 → 你刚才 `--out` 用了别的文件名（比如 `homography_hand.json`），把它复制覆盖：

```
Copy-Item homography_hand.json homography.json -Force
```

（或运行 grasp.py 时加 `--homography 文件名.json` 指向最新标定，但推荐直接统一成 `homography.json`。）

✅ 完成标准：`homography.json` 的修改时间 = 刚才标定时间。

---

## 4. 标定 base_x / base_y（机械臂或①动过 → 必做）

### 4.1 方法 A：J1 投影点在画面内（推荐布局下适用）

```
python calib_base.py --source 0 --homography homography.json
```

1. 弹窗出现后，**点击 J1 舵盘中心正下方台面的投影点**（放个硬币在台面上对准舵盘正下方，点硬币）；
   - ⚠️ 别点舵盘本身：舵盘在台面上方几厘米，点它会有透视误差。
2. 多点几次（5~10 次）自动取平均，窗口顶部实时显示当前换算的 base；
3. 按**空格/回车**写入 config.json，`q` 退出。

### 4.2 方法 B：J1 投影不在画面内（--ref 参考点法）

```
python calib_base.py --ref --source 0 --homography homography.json
```

1. 在画面内的台面上放一个标记物（硬币/笔尖/夹爪夹的小方块贴台面）；
2. 画面里点击该标记物（多点几次取平均）；
3. 按空格，终端提示输入：`标记物相对 J1 投影的偏移 dx,dy (cm)`；
4. 用尺子量标记物相对 J1 投影的偏移输入，如 `5,8` = 右 5cm、前 8cm；
   - 符号规则：标记物在 J1 **左侧** → X 为负；在 J1 **后方** → Y 为负。
5. 自动写入 config.json。

### 预期 / 完成标准

- ✅ 终端打印"已写入 config.json"，`base_x`/`base_y` 已更新；
- 推荐布局下 base_x ≈ +10、base_y ≈ -10（以实测为准，别手填）；
- 偏差大 → 重跑并多点取平均，或检查②④是否对齐。

---

## 5. 更新 ROI（H 变了必做，一条命令自动算）

```
python set_roi.py --homography homography.json --width 250 --height 200
```

原理：工作区四角毫米坐标已知（①(0,0) ②(250,0) ③(250,200) ④(0,200)），用 H 反算回像素 → 包围盒 + 15px 余量 → 写入 `config.json` 的 `roi`。

### 预期输出

```
角 ①(0,0)   mm(0,0)   -> 像素 (58, 423)
角 ②(W,0)   mm(250,0) -> 像素 (541, 418)
...
ROI = [41, 19, 515, 419]（覆盖整个工作区 + 余量 15px）
已写入 config.json 的 roi
```

### 完成标准 / 失败排查

- ✅ 出现"已写入 config.json 的 roi"；
- 打印的 ROI 超出画面（如 640×480 会警告）→ 工作区超出视野，调摄像头高度/角度后回到第 2 步重标；
- 以后工作区尺寸变了 → 同一命令改 `--width/--height`。

---

## 6. 验证 base（必做，第 4 步对错这里见分晓）

### 6.1 验证①：目标在 J1 正上方 → arm ≈ (0,0)

1. 放一个小目标（如蓝色方块）在 **J1 舵盘中心正下方台面**（臂先转开避免遮挡）；
2. 运行：

```
python grasp.py --source 0 --homography homography.json --sim
```

3. 在画面里确认该目标有检测框，**看终端打印的 `arm(x,y)cm`**（选目标时打印）；
4. ✅ 应约 **(0.0, 0.0)**，±1cm 内可接受。

### 6.2 验证②：目标在已知位置 → arm ≈ 实测偏移

1. 把目标放在任意位置，用尺子量它相对 J1 投影的偏移 (dx, dy)（臂右=+X、臂前=+Y）；
2. 终端 arm 读数应 ≈ (dx, dy)。

### 失败排查

- 所有位置 arm 系统性偏一个方向 → ②④ 没严格沿臂右/臂前 → 回 1.2 重摆、重做第 2 步；
- 只是偏一个固定量 → base 不准 → 重做第 4 步并多点取平均。

✅ 两个验证都过，坐标链路正确，进入下一步。

---

## 7. 检测参数（config.json）

1. 打开 `vision/config.json`（第 5 步已自动设好 roi，不用手改）；
2. 跑 `grasp.py --sim` 看识别效果：
   - **工作区内所有目标都能识别** → 本步完成，直接进第 8 步；
   - **远处目标识别不到**（其他位置正常）→ 把 `"min_area": 500` 调小到 200~300；
   - **画面外杂物被误识别** → 说明 roi 框太大，`set_roi.py --margin 30` 或手改 roi 收紧；
   - **某个颜色识别不到**（其他颜色正常）→ 调该颜色阈值（如绿色 `[35,60,60]~[90,255,255]`，S/V 下限放宽、H 上限放宽）。

✅ 完成标准：工作区内目标稳定识别、画面外无杂物误识别。

---

## 8. J5 方向校准（wrist-offset / grip-conv，摄像头动过 → 重做）

**目标：夹爪两指贴住目标两条长边、跨过宽度**（不压短边、不抓对角）。

### 8.1 看辅助线

1. 放一个**矩形/方形**目标在画面中心区域；
2. 运行 `grasp.py --sim`，画面有两条辅助线：
   - **红线 = 目标长边方向**
   - **绿线 = 夹爪张开方向（两指连线）**
3. 按 `[` / `]` 调整 wrist-offset（每次 ±2°），直到**绿线垂直红线**；
4. 按 `s` 保存到 config.json。

### 8.2 真机试抓判定

1. 真机抓一次（第 9 步的完整命令）；
2. 看两指落点：
   - ✅ 两指贴住两条**长边** → 正确，本步完成；
   - 两指压在两条**短边**（方向差约 90°）→ 是**结构约定角**问题，不是视觉偏差：加 `--grip-conv 90`（或 -90）再回 8.1 重新看绿线；
   - 方向对但落点偏 → 进第 9 步微调。

---

## 9. 试抓微调（off-x / off-y / off-z）

真机完整抓一次（模式1 逐步，空格推进）：

```
python grasp.py --source 0 --homography homography.json --port COM7
```

观察落点，每次 **±0.3~0.5cm** 一档调：

| 现象 | 参数 |
|---|---|
| 夹爪偏**左** → 加 `--off-x 0.5`；偏**右** → `--off-x -0.5` | （正=右） |
| 夹爪偏**后** → 加 `--off-y 0.5`；偏**前** → `--off-y -0.5` | （正=前） |
| 夹爪**压到物体** → `--off-z -0.3`；离**太高** → `--off-z 0.3` | （负=更低） |

✅ 完成标准：落点正中，闭合能稳稳抓住并抬起。

---

## 10. 正式运行

```
python grasp.py --source 0 --homography homography.json --port COM7 --mode 1
```

- 模式1 逐步（空格推进）：调试用；
- 模式2 自动连续：演示用；
- 常用附加：`--color green`（只抓绿色）、`--tilt-max 45`（默认 45，远目标自动前倾，不用改）。

## 速查表：发生什么 → 重做哪步

| 发生了什么 | 重做 |
|---|---|
| 摄像头移动 / 角度变 | 1 摆放 → 2 homography → 4 base → 5 ROI → 8 方向 |
| 机械臂底座移动 | 4 base → 8 方向验证（homography 不用，摄像头没动） |
| 标定点①位置变 | 2 homography → 4 base → 5 ROI → 8 方向验证 |
| 只换目标物 / 只调颜色 | 什么都不用重标，直接抓 |

## 常见问题速查

| 现象 | 原因 | 处理 |
|---|---|---|
| mm 坐标全乱（目标在①却显示 (34,228)） | **用错标定文件**（旧 homography.json） | 第 3 步：检查时间戳，用最新标定覆盖 |
| arm 系统性偏一个方向 | ②④没沿臂右/臂前 | 重摆标定点 → 重标 homography |
| 方向永远差 90°（压短边） | 结构约定角 | `--grip-conv 90`（或 -90），别硬调 wrist-offset |
| 目标离 J1 越远偏差越大 | 摄像头倾斜过大 | 调垂直 → 重标 |
| 远处目标识别不到 | min_area 太大 | 调到 200~300 |
| 某个颜色识别不到 | 阈值/光照 | 放宽该颜色 S/V/H 范围 |
| 前倾到 45° 还够不到 | 工作区离 J1 太远 | 工作区整体靠近 J1 → 重标 |
